**************


エラーの原因は、**DB に `auth_user` テーブル（Django のユーザーテーブル）が存在しない**ことです。
＝＞ 認証処理（/login/）でユーザーを検索しようとしてコケています。

まずは「どの DB を見ているか」「auth のマイグレーションが適用されているか」を確認し、必要ならマイグレーションを適用（または正しい DB を指すように設定）します。

---

## 1) まず現状の診断

```bash
# どのアプリのマイグレーションが適用済みか確認
python manage.py showmigrations auth
python manage.py showmigrations sessions
python manage.py showmigrations contenttypes
```

**→ 先頭に \[X] が付いていなければ未適用です。**

さらに、**今どの DB を参照しているか**を確認します：

```bash
python manage.py shell
```

```python
from django.conf import settings
from django.db import connection
print("DB ENGINE:", settings.DATABASES["default"]["ENGINE"])
print("DB NAME:", connection.settings_dict["NAME"])
exit()
```

* SQLite の場合は `DB NAME` に **db.sqlite3 のフルパス**が出ます。
  ここが想定と違うパス（別ディレクトリ）になっていると、**別の DB を見に行っている**＝テーブルがない、という事態になります。

---

## 2) 解決手順（標準的な SQLite 想定）

1. **必要アプリが `INSTALLED_APPS` に入っているか確認（settings.py）**

   ```python
   INSTALLED_APPS = [
       'django.contrib.admin',
       'django.contrib.auth',
       'django.contrib.contenttypes',
       'django.contrib.sessions',
       'django.contrib.messages',
       'django.contrib.staticfiles',
       # 自アプリ
       'accounts',  # ←あなたのアプリ名
   ]
   ```

2. **マイグレーションを適用**

   ```bash
   python manage.py migrate
   # もしくはピンポイントで
   python manage.py migrate contenttypes
   python manage.py migrate auth
   python manage.py migrate sessions
   ```

3. **管理ユーザーを作成（未作成なら）**

   ```bash
   python manage.py createsuperuser
   ```

4. **サーバー再起動**

   ```bash
   python manage.py runserver
   ```

---

## 3) それでも直らない時の“あるある”と対処

### A. 「No migrations to apply」と出るのにテーブルが無い

* **別の DB ファイルを参照している**可能性が高いです。
  上のシェル出力で `DB NAME` を再確認してください。
  `settings.py` の `DATABASES['default']['NAME']` が意図したパスか見直しを。

  ```python
  # 例: settings.py (SQLite)
  from pathlib import Path
  BASE_DIR = Path(__file__).resolve().parent.parent
  DATABASES = {
      'default': {
          'ENGINE': 'django.db.backends.sqlite3',
          'NAME': BASE_DIR / 'db.sqlite3',   # ← ここがズレていないか
      }
  }
  ```

* 誤った場所に空の `db.sqlite3` ができていて、そっちを参照しているケースもよくあります。

### B. カスタムユーザーモデルを途中で導入した／`AUTH_USER_MODEL` を後から変更した

* 既にマイグレーションを切った後に `AUTH_USER_MODEL` を変えると整合が取れなくなります。
  開発段階でデータが無いなら、**DB を削除してやり直す**のが早いです（SQLite なら `db.sqlite3` を削除 → `migrate`）。

### C. `INSTALLED_APPS` に `django.contrib.auth` などが抜けている

* 抜けていると当然テーブルが作られません。必ず入れてください。

---

## 4) クイック修復のコマンドまとめ

```bash
# 参照DB確認（前述の shell スニペット）
python manage.py shell

# 必要ならマイグレーション適用
python manage.py migrate

# 念のため auth だけ個別に
python manage.py migrate auth

# 管理ユーザー作成（未作成なら）
python manage.py createsuperuser

# 再起動
python manage.py runserver
```
